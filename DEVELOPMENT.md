## Что объяснить

- Flask обрабатывает HTTP-запросы, Jinja формирует HTML, SQLite хранит данные.
- Blueprint `creation` принадлежит ветке формы, `management` — ветке списка.
- Обе части используют общий контракт данных в `store.py`.
- Поля проверяются на сервере; браузерная проверка дополняет её.
- Изменения выполняются POST-запросами, формы защищены CSRF-токеном.
- Значения передаются в SQL как параметры; HTML экранируется Jinja.
- Тесты используют временную базу и не изменяют рабочие заявки.
- После объединения форма редактирования использует общие поля создания.
- В контейнере приложение обслуживает Gunicorn, данные вынесены в Docker volume.
